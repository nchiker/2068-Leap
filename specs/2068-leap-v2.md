## Goal
Audience/experience: BASIC programmers on a stock 48K TS2068, unchanged instant-on experience.
Core loop or value: eliminate 2068-Leap's biggest user-visible language limitations without sacrificing compactness/performance — now known to require a Phase 0 relocation step before any language feature can be funded.
Smallest convincing slice: Phase 0 P0.1 (benchmark authoring, zero product-code risk) — see docs/FIRST_MILESTONE.md.
Non-goals: unchanged from Phase 1 — replacing 2068-Leap's architecture with structured-basic-poc's; a bytecode VM; reference-counted string heap; general multi-module registry; RAM expansion; mandatory external hardware. Added in Phase 2: de-duplication as a ROM-recovery strategy (foreclosed by evidence).

## Target Profile
Targets/toolchain/delivery: unchanged — TS2068, Z80A, sjasmplus, 24KB ROM (16K HOME + 8K EXROM chunk 6), 48K RAM.
Platform decisions: unchanged.
Deferred decisions: procedures/functions (downgraded from committed to desirable-and-deferred in Phase 2), dynamic-length scalar strings beyond 31 bytes (newly deferred in Phase 2), plus everything already deferred in Phase 1.
