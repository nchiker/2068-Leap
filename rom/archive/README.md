# Archived diagnostic files

These are one-off diagnostic tools built to chase specific bugs during
development. Each bug they were built for is now fixed and confirmed
working. Kept here (not deleted outright) in case the diagnostic
*technique* is worth reusing for a future bug, but none of these
should be assembled or trusted as current — several are already stale
relative to the real kernel/basic files they were copied from or
targeted.

- **editor_navdebug_copy.asm** — a modified COPY of kernel/editor/editor.asm
  with border-color markers (red/yellow/cyan/green) added around the
  UP/DOWN nav-hook dispatch, plus a cycling hex counter proving the loop
  stayed alive. Built to diagnose the nav-hook dispatch bug. Already
  stale: missing EDIR_DELETE_LINE/EDIR_INSERT_LINE/EDIR_NEXT_ERROR/
  EDIR_PREV_ERROR, which the real editor.asm has gained since. Do not
  assemble this — diff it against the real file if the border-color
  technique itself is useful again.
- **test_nav_hook_debug.asm** — the test harness that used the copy
  above, combined with a CUR_EDIT_POS/CUR_EDIT_INDEX hex overlay. Same
  staleness caveat applies transitively.
- **test_editor_debug.asm** — numeric diagnostic (raw keycode, cursor
  offset, scanned content length) for the editor, bypassing the normal
  EDITOR_ENTER/EDITOR_LOOP flow. Built to diagnose a display bug in the
  editor.
- **test_basic_debug.asm** — REPL diagnostic that dumps VAR_TABLE's raw
  stored value for variable X as hex after every RUN, to separate
  storage bugs from PRINT display bugs.
- **test_basic_nav_debug.asm** — overlays CUR_EDIT_POS/CUR_EDIT_INDEX/
  VIEW_TOP_INDEX as hex at fixed bottom rows on top of the normal
  BASIC_REDRAW_PROGRAM rendering. Built to diagnose committed lines
  seeming to vanish and UP not showing existing text during multi-line
  navigation testing.

None of these are referenced by rom/main.asm or any current build.

## Archived pre-EXROM preload harnesses (2026-08-19 code review)

Twenty `test_preload_*.asm` files, moved here from `rom/` in the same
pass that found and fixed a stray-code issue affecting all of them
(see main README's Architecture/Housekeeping notes). Each was a
preload test harness generated by `tools/preload_gen.py` before the
checker+SAVE/LOAD EXROM migration (2026-08-18/19). Two separate
staleness problems, found together:

1. All 21 (including the one kept live) directly `INCLUDE
   "kernel/storage/storage.asm"` without first defining that file's
   required `STORAGE_MATH_MULTIPLY16`/`STORAGE_MATH_DIVIDE16` EQUs —
   this would fail to assemble as-is. Fixed for the one file kept
   live (`rom/test_preload_expect_end_valid.asm`) and for
   `tools/preload_gen.py`'s own template, so future-generated files
   won't repeat it. Left as-is in the 20 files here, since they're
   archived rather than fixed forward.
2. These 20 (unlike the one kept live) also never gained the EXROM
   boot sequence at all (no `EXROM_JUMPTABLE_HOME_SIDE`/`KTAB_LIST` —
   compare against `rom/test_basic.asm` or the one current preload
   file) — basic.asm's `BASIC_RUN` unconditionally pages into EXROM
   now, so any of these would page into garbage the moment RUN (or
   any checker-invoking action) runs, even if the storage.asm issue
   above were fixed. Each already served its purpose and is
   referenced in `docs/programmers_reference.md` as history for the
   bug it helped find/confirm — kept here for that record, not for
   reassembly.

Only `rom/test_preload_expect_end_valid.asm` remains in `rom/` as a
live, EXROM-aware preload harness (used for the FOR/NEXT hardware
confirmation). Regenerate any of these archived ones from a plain-
text listing via the now-fixed `tools/preload_gen.py` if the specific
scenario needs retesting under the current build.

## Archived: SAVE/LOAD test harnesses (2026-08-24)

`test_storage.asm` (Home-only primitive test for the from-scratch tape
protocol) and `test_storage_save_toolarge.asm` (one of `tools/
fuse_load_inject.py`'s generated harnesses). Archived together with
`kernel/storage/storage.asm` itself (`kernel/storage/archive/`) — see
that archive's own README.md for the full reasoning. Neither will
assemble as-is once reassembled standalone, since both `INCLUDE`
`kernel/storage/storage.asm` by its old path; update the path to
`kernel/storage/archive/storage.asm` first if either is ever needed
again.
