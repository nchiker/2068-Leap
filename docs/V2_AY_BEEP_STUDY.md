# V2 maintenance study: AY-based BEEP, SOUND register 0, startup chime

Branch `study/ay-beep` (worktree `~/2068-Leap-study/ay-beep`), based on the release tag `v2.0.0-emu.1` (`f4cabad`). Local only: nothing merged, pushed or tagged. `v2-development`, `docs/v2-user-manual`, the tag, the release images and the qualification evidence are untouched; `make build EXTRA_DEFS=` on this branch still produces the accepted images (HOME `dddd4cbb...`, EXROM `c1804641...`, checked).

**Follow-up:** [`V2_CLASSICBEEP_STUDY.md`](V2_CLASSICBEEP_STUDY.md) (branch `study/classicbeep`) audits the removed software beeper, adds a shared frame wait (HOME 19 / EXROM 26 free, BREAK ends a `BEEP`, a `PAUSE` wrap defect fixed) and puts the loudspeaker BEEP in an optional package.

Inputs: `V2_BEEP_SOUND_MODE_COMPATIBILITY.md`, `V2_MAINTENANCE_BACKLOG.md` (items M-1, M-2) and `V2_DOCUMENTATION_FINDINGS.md` on `docs/v2-user-manual`; the software-beeper prototype `study/beep-compat` (`ccb78a4`); the stock TS2068 ROM in ZEsarUX 13.0.

**Result.** Sinclair-style `BEEP seconds,semitones` on the AY chip, the `SOUND` register-0 correction and a startup chime all fit in the original ROM. With the original chime kept note-for-note (regenerated by a loop instead of a table) the candidate has **HOME 13 / EXROM 20 bytes free**; with a smaller three-note chime, **HOME 35 / EXROM 38**. The AY version is smaller than the software-beeper prototype, more accurate in pitch on a real TS2068 up to three octaves above middle C, and leaves interrupts on. Keeping the chime's current implementation unchanged does **not** fit (EXROM 22 bytes short).

## 1. The sound subsystem as released (measured, `build/*.sym`)

| Piece | Bank | Bytes | What it does |
|---|---|---|---|
| `OP_BEEP` | HOME | 10 | pops pitch, duration (truncated to integers), calls `SOUND_BEEP` |
| `SOUND_BEEP` (`kernel/sound/sound.asm`) | HOME | 55 | toggles port `$FE` bit 4 (the loudspeaker, not the AY), `222 + 52 x pitch` T-states per cycle, `DI` for the whole note |
| `OP_SOUND` | HOME | 16 | pops data, register; calls the EXROM slot `SOUND_EXROM` |
| `VM_ERR_INVALID_SOUND_REGISTER` | HOME | 4 | runtime error 8 |
| EXROM slot for `SOUND_EXROM` | EXROM | 6 | `call V2_VERIFY_KTAB` / `jp` |
| `SOUND_EXROM` (`rom/exrom_sound.asm`) | EXROM | 17 | rejects 0 and 17+, `OUT ($F5)` register, `OUT ($F6)` data; B and C kept |
| `STARTUP_CHIME` + `CHIME_TABLE` + `CHIME_DELAY` | EXROM | 39 + 78 + 18 = 135 | C4/E4/G4 chord on channels A/B/C: register 0 by raw `OUT`s (SOUND_EXROM refuses 0), 37 register/value or delay entries, `CHIME_DELAY` polls `FRAMES` |

Chime, as traced from the release image (`tools/maint/chime_trace.py`, frame = display interrupt after the first write): frame 0: R0..R5 = periods 421/334/281, R7 = `$F8` (tones on, noise off, I/O ports output), R8..R10 = 0, R8 = 4; then R8 8, 12 at frames 3, 6; R9 4/8/12 at 9/12/15; R10 4/8/12 at 18/21/24; release at 46 (all 8), 49 (all 4), 52 (all 0). It ends with the AY quiet, R7 = `$F8`.

Shared or duplicated: nothing between BEEP and the chime (different hardware). Three separate frame waits exist (`OP_PAUSE`, `CHIME_DELAY`, the editor's key timing), each a few bytes; the chime and `OP_SOUND` share `SOUND_EXROM`. Reusable services: the VM float stubs (`VM_FLOAT_PUSH_FIRST`, `VM_CALC_MUL_STUB`), the EXROM calculator slots (`CALC_INT_TO_FP`, `CALC_FP_TO_INT`), `SOUND_EXROM`, `FRAMES` and the ISR. V2's reduced calculator has no `exp`, so the stock ROM's way of computing 2^(n/12) is not available.

Stock ROM, for comparison: `BEEPER` `$03F3-$0435` (67 bytes) and `BEEP` `$0436-$04A9` (116) + REPORT-B (2) are the Spectrum 48K routines, byte for byte except addresses and four timing bytes; they rely on the full calculator (`exp`). The 60-byte semitone table after them (`$04AC`) is not used by `BEEP`. Measured in the emulator (`stockbeep` probe, consistent with the earlier oracle): `0 <= seconds <= 10`, semitones `-60..69`, fractional semitones interpolated, error B outside; durations under one cycle play nothing; `DI` while sounding; on a real TS2068 (3.528 MHz) every stock note is 14 cents sharp, because the routine assumes 3.5 MHz.

## 2. The AY BEEP (rom/v2_ay_beep.asm)

* **Pitch.** Semitones are popped as an integer (a fraction is cut off toward zero, the documented VM rule: `BEEP 1,0.5` and `BEEP 1,-0.5` both play middle C). Range `-60..69` like the stock ROM, else runtime error 15. Period = `110250 / f` (AY clock 1.764 MHz = 3.528 MHz / 2; tone = clock / 16 / period), from a 12-entry table of `16 x period` for the octave starting at A0 (-39), shifted right by the octave and rounded. The 12-bit period cannot go below 27.5 Hz: **-60..-40 play A0** (documented; the alternative, an error, costs the same bytes but stops stock programs that use very low "thud" notes).
* **Duration.** `seconds x 120` through the calculator, rounded to the nearest display frame (1/60 s on a TS2068). Negative or more than 273 s: error 15 (the stock limit was 10 s, from its 16-bit cycle count; the AY has no such limit). Under half a frame (< 8.3 ms): plays nothing, as the stock ROM is silent for under one cycle.
* **Sound.** Channel A: R0/R1 = period, R7 read-modify-write (tone A on, noise A off, every other bit kept, including the I/O-port direction bits), R8 = 15 (fixed level), then `HALT` once per frame, then R8 = 0. Channels B and C, noise period, envelope and I/O ports are untouched. Interrupts stay **on**: `FRAMES` advances, the keyboard is scanned, BREAK is still detected by the ISR (but, as with the stock `BEEP`, a note is not cut short by it).
* **No frame sync at the start**, deliberately: a `BEEP` ends just after an interrupt, so consecutive notes follow each other with no gap and the tempo is exact; an isolated note's first frame is partial (it lasts between n-1 and n frames). A sync `HALT` (1 byte) was tried and removed: it inserted a one-frame silence between every pair of notes.

### Placement and cost (assembled)

The code is the same whichever bank a piece lives in; the switches `V2_MAINT_AYB_PERIOD_HOME`, `_PLAY_HOME`, `_WAIT_HOME` only balance the budgets. HOME reaches EXROM through one new slot (`AY_BEEP`, 6 bytes, KTAB magic `$1A` -> `$1B`); EXROM calls HOME directly.

| Piece | Bytes |
|---|---|
| `OP_BEEP` (HOME) | 38 |
| `AY_BEEP_PERIOD` + table | 46 + 24 |
| `AY_BEEP_PLAY` | 41 |
| `AY_WAIT_FRAMES` (shared with the chime) | 7 |
| slot + `AY_BEEP` entry | 6 + 3 |
| removed: old `OP_BEEP` + `SOUND_BEEP` | -65 |
| **BEEP net** | **+100** |
| SOUND register 0: `SOUND_EXROM` -3, `OP_SOUND` -2 (`ld b,l` / `ld c,l`) | -5 |

RAM: none (stack only; no sysvar, no scratch cell).

## 3. BEEP and SOUND together

Policy chosen: **BEEP takes channel A for the duration of the note and leaves it silent.** After a `BEEP`, channel A has level 0 (an envelope-mode level, 16, is replaced), R0/R1 hold the note's period, and R7 has tone A on / noise A off; a program that used channel A with `SOUND` writes its settings again. Channels B and C and all other bits are untouched, so `SOUND` music on B/C continues under a `BEEP`.

Alternatives: reserving a channel is what this is (A). Saving channel A's four registers (R0, R1, R7, R8) before the note and writing them back after was built as a switch (`V2_MAINT_AYB_RESTORE`) and assembled: **+56 bytes**. It does not fit with the original chime (chime C: EXROM 36 short) and with the arpeggio fits only if the player moves to EXROM (about 7 bytes left); it was not run. No sound manager.

Tests (`tools/maint/ay_beep_tests.py`, all pass): `SOUND` B/C periods and levels and R7 = 56 survive a `BEEP`; R7 255 -> 254, 0 -> 8, 65 -> 72, 182 -> 190; `SOUND` on channel A then `BEEP`: A takes the note and is silent after; `BEEP` then `SOUND 0,200: SOUND 1,0: SOUND 8,10` writes R0 = 200, R1 = 0, R8 = 10.

## 4. SOUND register 0

`SOUND_EXROM` no longer rejects 0 (the stock check is `CP $11` only; its `DEC A / INC A / JP M` never fires for 0). EXROM -3 bytes, measured (`sound0` build: EXROM 25 -> 28). Tests: `SOUND 0,123` writes R0 = 123, `SOUND 1,5` R1 = 5, `SOUND 15,7` and `SOUND 16,9` accepted, `SOUND 17,1` and `SOUND 20,1` runtime error 8. The chime's raw register-0 `OUT`s become an ordinary table entry.

Side effect to note (pre-existing behaviour, not changed): `OP_SOUND` uses only the low byte of the register, so `SOUND 256,x` now writes register 0 (it was an error because 0 was refused) and `SOUND 257,x` writes register 1 as before; the stock ROM rejects both. Checking the high byte would cost about 5 HOME bytes; left as an owner decision (same class as finding B4).

## 8. Limitations and emulator facts

* ZEsarUX 13.0's TS2068 runs a 3.5 MHz CPU, 50 Hz frames (69 888 T-states) and an AY clock of 1.7734 MHz. A real TS2068 has 3.528 MHz, 60 Hz and 1.764 MHz. So in ZEsarUX every `BEEP` lasts 20 % longer (60 frames at 50 Hz for one second; `PAUSE` behaves the same) and sounds 0.53 % (9 cents) sharp; the tests check frames and register values, not wall-clock seconds.
* ZEsarUX snapshots do not restore the interrupt mode (a restored machine reports IM 0; a cold boot is IM 1). Harmless here (IM 0 with an idle bus executes `RST $38`), but worth knowing for `qharness`.
* Durations are whole frames; an isolated note may be up to one frame short.
* Above about +36 semitones the 12-bit period is coarse (up to 77 cents at +60..69).
* `BEEP` waits with `HALT`: if a program switches off the frame interrupt (port `$FF` bit 6) a `BEEP` never ends -- the same as `PAUSE`.
* Nothing was listened to on hardware. Physical checks to add to the hardware checklist: the chime and a scale through the TV sound; that the AY level 15 is comfortable next to the old beeper; that STICK still reads after the chime (unchanged: R7 = `$F8` as in the release).

## 10. Recommendation

For the maintenance release: **AY BEEP + SOUND register 0 + chime C** (this branch's default build).

* It does what the owner asked: Sinclair `BEEP seconds,semitones`, `SOUND` 0-16 like the stock ROM, and the startup chime **preserved** -- the same register writes at the same frames as the release (plus one inaudible noise-period write), now generated by 86 bytes of code that shares `SOUND_EXROM` and BEEP's frame wait instead of 135 bytes of table.
* It fits with room: HOME 13, EXROM 20 bytes free (release: 54 / 25). No RAM. No package ABI change (the new EXROM slot is internal; the HOME/EXROM magic moves to `$1B`).
* It is better than the software prototype on every measured axis except fractional pitch (neither has it) and duration granularity (frames instead of cycles), and it keeps interrupts running.

Owner decisions:

1. **Chime C or B.** If reserve matters more than the exact chime, option B (three rising notes, 43 bytes) leaves **HOME 35 / EXROM 38**: one switch (`-DV2_MAINT_CHIME_B -DV2_MAINT_AYB_PLAY_HOME -DV2_MAINT_AYB_WAIT_HOME`, no period-in-HOME). Option A (the release chime's own code, 6 / 3 free) is not recommended: same sound as C, less reserve.
2. **Low notes:** play A0 for -60..-40 (built) or error 15 (same cost).
3. **`SOUND 256,x`** now writes register 0 (low byte only, pre-existing rule); checking the high byte costs about 5 HOME bytes.
4. Optional later: fractional semitones (about +30 bytes), BREAK ending a long BEEP (about +6), restoring channel A after a BEEP (+56).

Before release: listen on real hardware (chime, a scale, levels), update the manual's `BEEP` and `SOUND` entries and examples on `docs/v2-user-manual` (the `sbeep` procedure becomes unnecessary; the register-0 note goes), add the focused suite to the maintenance qualification, and turn the build switches into plain source once the owner chooses (keep `kernel/sound/sound.asm`: the standalone and smoke ROMs still use `SOUND_BEEP`).
